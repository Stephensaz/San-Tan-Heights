# M7-027 — Milestone 7 Final Certification Suite

Status: BLOCKED (implementation and live-certification harness complete; live PostgreSQL 16+ execution unavailable in this sandbox)

Implemented a locked final-certification policy and deterministic final gate that requires all of the following before returning `PASS / GO`:

- candidate-bound PASS certification evidence bundle;
- valid immutable `FULL_APPROVAL` for the same candidate and evidence bundle;
- current go-live stop conditions = `CLEAR`;
- PASS certification for COHORT_25, COHORT_100, COHORT_500, and REMAINING_FLEET;
- all hard-zero metrics equal zero; and
- executed live PostgreSQL certification for migrations, immutability triggers, least-privilege grants, locking/concurrency behavior, and backup/restore behavior.

The final gate returns `BLOCKED / NO_GO` when code/evidence requirements pass but live PostgreSQL certification has not actually executed.

## Live PostgreSQL certification harness

Added `scripts/certification/run_live_postgres_certification.py`, which is designed to run unchanged against an isolated PostgreSQL 16+ certification instance. It:

1. verifies PostgreSQL 16+ and applies every repository migration with `ON_ERROR_STOP`;
2. performs actual forbidden mutations against READY report/render rows and requires the live immutability triggers to reject them;
3. verifies `sth_public_delivery` can read the sanitized Public projection but cannot read base report tables or mutate publication pointers;
4. runs two concurrent PostgreSQL sessions against the report-version counter and proves row-lock serialization;
5. performs a real `pg_dump` / `pg_restore` into a second database and verifies restored fixture data and immutability triggers;
6. emits machine-readable JSON evidence with a canonical SHA-256 evidence fingerprint.

`load_live_postgresql_evidence()` verifies the evidence fingerprint before M7-027 consumes the result.

During harness preparation, static review found and corrected a real live-migration defect in `0143_least_privilege_completion.sql`: the Public report projection referenced nonexistent `r.report_version`; it now correctly selects `r.version_number AS report_version`.

## Current environment blocker

This execution sandbox has:

- no `postgres`, `initdb`, `pg_ctl`, or `psql` binaries;
- no Docker/Podman/nerdctl runtime;
- no psycopg/psycopg2/asyncpg driver;
- outbound package-network access blocked, preventing installation of PostgreSQL packages.

Therefore the live PostgreSQL checks still cannot be executed here. M7 remains BLOCKED until the harness is run on a provisioned PostgreSQL 16+ certification environment and all five required checks return PASS.

See `docs/runbooks/M7-027-LIVE-POSTGRES-CERTIFICATION.md` for the exact execution procedure.

## Disposable PostgreSQL 16 CI execution path

Added `.github/workflows/m7-live-postgres-certification.yml` so the live gate can be executed without maintaining a long-lived database host. The workflow:

- provisions an isolated `postgres:16` service container;
- installs the PostgreSQL 16 client tools on an Ubuntu 24.04 runner;
- runs the repository's live certification harness unchanged;
- independently verifies the evidence fingerprint and all five required PASS checks;
- uploads `live-postgres-evidence.json` as a retained workflow artifact even when the harness fails; and
- fails the workflow if the harness or evidence verification does not pass.

This makes the external execution step reproducible, but it does **not** change the ticket's BLOCKED status by itself. M7-027 remains BLOCKED until an actual workflow run (or equivalent PostgreSQL 16+ execution) produces verified all-PASS evidence that is then consumed by the final certification gate.

## Candidate-bound evidence finalization

Live PostgreSQL evidence schema v1.1 binds the evidence to both the exact frozen `candidate_fingerprint` and the corresponding `source_revision`. Executed evidence from a different candidate is a hard certification failure; unavailable/unexecuted evidence remains a BLOCKED external prerequisite.

Added `scripts/certification/finalize_m7_from_live_evidence.py`. The command verifies the evidence fingerprint, candidate binding, source revision, and all five required live checks. With `--apply`, it reruns the complete repository test suite and repository validator, preserves the evidence JSON under `artifacts/certification/`, and only then applies the guarded M7-027/M7 ACCEPTED and M8-001/M8 IN_PROGRESS transition. The transition refuses to run unless the repository is still in the expected M7 BLOCKED / M8 NOT_STARTED state.

## Automatic committed-candidate binding

Added `scripts/certification/freeze_repository_candidate.py`. A live GitHub certification run no longer relies on a manually invented candidate hash. The script requires a clean committed Git checkout and derives the immutable candidate binding from:

- the exact Git commit SHA;
- the exact Git tree SHA;
- repository `VERSION`;
- `CONTRACT-MANIFEST.yaml`;
- `BUILD-MANIFEST.yaml`;
- `ARCHITECTURE-LOCK.yaml`; and
- `STH-PRODUCTION-CERTIFICATION-v1.0`.

The GitHub Actions workflow now generates `candidate-binding.json` before running the PostgreSQL battery and passes the derived candidate fingerprint/source revision into the live evidence harness. An optional expected fingerprint may be supplied to make the workflow fail closed on candidate mismatch.

This repository is still not advanced to M7 ACCEPTED because the connected GitHub installation currently exposes no repository on which the live workflow can execute.
