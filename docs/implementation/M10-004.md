# M10-004 — New-Community Build Pipeline & Progressive Certification

Status: ACCEPTED

## Purpose

Consume an M10-003-approved onboarding bootstrap and execute a governed, stage-gated new-community build pipeline that proves identity, source, ingestion, evidence, report, presentation, and release-readiness boundaries progressively without allowing later stages to conceal an earlier failure.

## Accepted implementation

M10-004 adds:

- `registries/evolution/m10-004-progressive-build-pipeline-v1.0.yaml`
- `src/evolution/progressive_build_pipeline.py`
- `tests/unit/evolution/test_progressive_build_pipeline.py`
- `certification-evidence/m10-004/progressive-build-pipeline-acceptance-v1.0.json`

The executable pipeline enforces the frozen eight-stage sequence:

1. ONBOARDING_BOOTSTRAP
2. IDENTITY_JURISDICTION
3. SOURCE_ADAPTER_READINESS
4. CORPUS_ADMISSION_READINESS
5. EVIDENCE_PASSPORT_READINESS
6. REPORT_MATERIALIZATION_READINESS
7. PRESENTATION_INTEGRITY_READINESS
8. CANDIDATE_FREEZE

## Guardrails

- every stage requires successful predecessor evidence;
- a failed stage stops execution immediately;
- downstream stages cannot conceal or bypass an earlier failure;
- missing, extra, or mismatched stage inputs fail closed;
- each stage emits deterministic evidence fingerprints;
- final candidate fingerprint is produced only after all eight stages pass;
- protected community defaults are governed outside reusable core code;
- protected default leakage is rejected;
- publication is not performed by this ticket;
- waivers are prohibited.
