# M10-002 — Core Platform vs San Tan Heights Configuration Extraction

Status: NOT_STARTED

## Purpose

Classify and separate the accepted implementation into reusable core platform capabilities versus explicit San Tan Heights/community/source configuration without changing accepted San Tan Heights behavior or fingerprints.

## Frozen boundary

Every relevant platform component must be classified as one of:

- CORE_REUSABLE
- COMMUNITY_CONFIGURABLE
- COMMUNITY_SPECIFIC
- SOURCE_SPECIFIC

M10-002 may extract configuration boundaries, registries, adapters, templates, and bootstrap inputs. It may not change the accepted semantic behavior of San Tan Heights Production Baseline v1.0.0.

## Hard rules

- no mutation of the accepted San Tan Heights baseline;
- every extracted item retains exact source/path and lineage;
- community-specific constants may not remain hidden inside reusable core code;
- reusable core may not encode San Tan Heights identity, phase, parcel, builder, MLS, geography, or source assumptions;
- source-specific behavior must remain explicit;
- extracted configuration must reproduce the accepted San Tan Heights behavior and fingerprints;
- ambiguous classification fails closed to explicit review;
- no new intelligence method or presentation semantic may be introduced.

## Acceptance boundary

M10-002 is accepted only when the platform/component inventory is complete for the declared scope, every material component has a governed classification, hidden San Tan Heights assumptions are surfaced, extracted configuration reproduces the accepted baseline behavior, and no accepted baseline artifact is mutated.
