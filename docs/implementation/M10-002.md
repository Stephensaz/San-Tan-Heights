# M10-002 — Core Platform vs San Tan Heights Configuration Extraction

Status: ACCEPTED

## Purpose

Classify and separate the accepted implementation into reusable core platform capabilities versus explicit San Tan Heights/community/source configuration without changing accepted San Tan Heights behavior or fingerprints.

## Frozen boundary

Every relevant platform component is classified as one of:

- CORE_REUSABLE
- COMMUNITY_CONFIGURABLE
- COMMUNITY_SPECIFIC
- SOURCE_SPECIFIC

M10-002 extracts configuration boundaries, registries, adapters, templates, and bootstrap inputs. It does not change the accepted semantic behavior of San Tan Heights Production Baseline v1.0.0.

## Hard rules

- no mutation of the accepted San Tan Heights baseline;
- every extracted item retains exact source/path and lineage;
- community-specific constants may not remain hidden inside reusable core code;
- reusable core may not encode San Tan Heights identity, phase, parcel, builder, MLS, geography, or source assumptions;
- source-specific behavior remains explicit;
- extracted configuration reproduces accepted San Tan Heights behavior and fingerprints;
- ambiguous classification fails closed to explicit review;
- no new intelligence method or presentation semantic is introduced.

## Accepted implementation

Implemented artifacts:

- `config/communities/san_tan_heights-v1.0.yaml`
- `src/platform_config/community.py`
- `registries/evolution/m10-002-core-config-extraction-v1.0.yaml`
- `src/evolution/component_extraction.py`
- `tests/unit/evolution/test_component_extraction.py`
- `certification-evidence/m10-002/core-config-extraction-acceptance-v1.0.json`

The extraction layer:

- centralizes San Tan Heights community identity, county, property-ID prefix, listing service, and accepted baseline references in explicit configuration;
- classifies the declared repository scope as CORE_REUSABLE, COMMUNITY_CONFIGURABLE, COMMUNITY_SPECIFIC, or SOURCE_SPECIFIC;
- uses deterministic longest-prefix classification;
- scans reusable core files for hidden San Tan Heights/Pinal/ARMLS assumptions;
- fails closed on unclassified, ambiguous, or hidden-community core components;
- keeps residual San Tan Heights-bound runtime components explicit as COMMUNITY_SPECIFIC instead of hiding them on a marker allowlist;
- verifies the accepted San Tan Heights baseline manifest remains byte-identical;
- requires the actual repository declared scope—not only synthetic fixtures—to classify cleanly.
