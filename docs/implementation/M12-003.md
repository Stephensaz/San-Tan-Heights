# M12-003 — Listing Action Verification, Reconciliation & Controlled Rollback Layer

Status: ACCEPTED

## Purpose

Consume immutable M12-002 execution receipts, independently verify downstream state, reconcile receipt claims against observed external reality, keep mismatches and unknown outcomes explicit, and permit rollback only through a separately approved and authorized path.

## Accepted verification states

M12-003 now classifies verification as:

- `VERIFIED`
- `MISMATCH`
- `OUTCOME_UNKNOWN`
- `NOT_APPLICABLE`

A successful M12-002 receipt is not treated as proof of final downstream state.

Verification uses separately registered observed-state evidence.

## Reconciliation boundary

A `MISMATCH` or `OUTCOME_UNKNOWN` creates a governed reconciliation case.

Unknown or mismatched state cannot be silently resolved.

M12-002 receipts remain immutable and are never rewritten during reconciliation.

## Controlled rollback

Rollback is available only when the governed reconciliation state marks it `ELIGIBLE`.

Rollback requires:

- separate explicit human rollback approval;
- separate rollback authority;
- exact listing/action scope;
- authority revalidation at execution time;
- exact lineage to the original proposal, authorized action, execution receipt, verification, and reconciliation case;
- deterministic rollback idempotency.

A rollback is never automatic.

Duplicate rollback execution is suppressed.

If a rollback outcome is unknown, a repeated attempt is blocked as `BLOCKED_OUTCOME_UNKNOWN` rather than silently retried.
