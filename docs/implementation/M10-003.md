# M10-003 — Community Onboarding Contract & Bootstrap Generator

Status: IN_PROGRESS

## Purpose

Turn the accepted M10-002 core/configuration separation into a governed onboarding contract and deterministic bootstrap generator for a new community without copying San Tan Heights-specific assumptions into reusable platform behavior.

## Frozen boundary

M10-003 owns the minimum required onboarding inputs, validation rules, generated community configuration skeleton, source/identity declarations, baseline lineage placeholders, deterministic bootstrap manifest, and fail-closed rejection of incomplete or ambiguous onboarding requests.

M10-003 does not build a new community corpus, execute production ingestion, create new intelligence methods, mutate San Tan Heights Production Baseline v1.0.0, or certify a community for release.

## Required implementation

- define a versioned community onboarding contract;
- define required identity, jurisdiction, property-ID, source-system, and baseline-lineage fields;
- require explicit classification of community-specific and source-specific assumptions;
- generate deterministic bootstrap configuration and manifest artifacts;
- reject hidden San Tan Heights defaults;
- reject missing or ambiguous required inputs;
- preserve exact parent platform/baseline lineage;
- produce reproducible fingerprints for generated bootstrap artifacts;
- add unit tests and inherited M10/M8 regression coverage.

## Acceptance boundary

M10-003 may be accepted only when valid onboarding inputs deterministically generate the same bootstrap artifacts and fingerprints, invalid or incomplete inputs fail closed, no San Tan Heights-specific default leaks into generated output, accepted baseline artifacts remain unchanged, and all inherited regression/certification gates pass.
