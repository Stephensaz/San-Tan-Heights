# M10-001 — Baseline Evolution Governance & Change-Control

Status: IN_PROGRESS

## Purpose

Protect the immutable San Tan Heights Production Baseline v1.0.0 and establish the executable change-control boundary for every post-release modification before reusable-platform extraction begins.

## Frozen requirements

Every post-release change must have an immutable change request, explicit change class, semantic version class, exact parent baseline identity and fingerprint, component classification, impact/dependency scope, deterministic regression/recertification scope, structured baseline diff, candidate manifest/fingerprint, separate baseline/candidate state, governed promotion/rollback, and zero unresolved blocking exceptions before promotion.

Accepted baseline artifacts may never be edited in place.

## Acceptance boundary

M10-001 is accepted only when code and tests prove that an accepted baseline is immutable, every material change becomes a separate candidate with exact parent lineage, unclassified or ambiguous changes fail closed, emergency changes remain governed, candidate diffs and recertification scope are deterministic, promotion requires required evidence and zero blocking exceptions, rollback restores an exact certified baseline/candidate artifact, and historical baselines remain immutable.
