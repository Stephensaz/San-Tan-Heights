## Portfolio isolation

Each portfolio member preserves its own:

- community namespace;
- candidate fingerprint;
- candidate-package fingerprint;
- release-request fingerprint;
- freshness record;
- approval record and approval authority;
- rollback baseline id;
- rollback baseline fingerprint;
- rollback eligibility.

Cross-community namespace, approval-record, and rollback-fingerprint collisions are rejected.

## Fail-closed portfolio decision

The portfolio returns `GO` only when every community independently passes.

Any one member with:

- factory failure;
- missing candidate package;
- stale freshness;
- unresolved exceptions;
- missing approval;
- approval-authority mismatch;
- namespace mismatch;

forces the full portfolio decision to `NO-GO`.

A passing community remains visibly PASS when another member fails. Member outcomes are never averaged or collapsed into a blended result.

## Release boundary

The portfolio artifact is:

- immutable release-readiness evidence;
- `published: false`;
- `readiness_only: true`.

M10-009 does not publish or promote any community.
