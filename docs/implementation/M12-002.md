# M12-002 — Authorized Listing Action Execution & Receipt Layer

Status: ACCEPTED

## Purpose

Consume an immutable M12-001 governed action proposal plus explicit human approval and separately validated execution authority, then create an execution-ready authorized action and immutable execution receipt with exact proposal, approval, authority, adapter, request, response, and outcome lineage.

## Accepted execution controls

M12-002 now requires:

- exact human approval bound to the proposal fingerprint;
- approval decision `APPROVED`;
- independent execution authority;
- exact listing and action scope;
- valid authority time window;
- authority revalidation immediately before any adapter call;
- deterministic idempotency;
- immutable execution receipt.

## Execution outcomes

Receipts distinguish:

- `SUCCEEDED`
- `FAILED`
- `OUTCOME_UNKNOWN`
- `DUPLICATE_SUPPRESSED`
- `BLOCKED_OUTCOME_UNKNOWN`

A claimed success without an external receipt ID is downgraded to `OUTCOME_UNKNOWN`.

Adapter exceptions or request/response binding mismatches also become `OUTCOME_UNKNOWN`.

## Duplicate and retry boundary

The same deterministic idempotency key cannot invoke the adapter twice.

Any prior receipt suppresses duplicate execution.

If the prior receipt is `OUTCOME_UNKNOWN`, the repeated attempt becomes `BLOCKED_OUTCOME_UNKNOWN` and no adapter call occurs.

No silent retry is permitted.

## Authority separation

M12-002 does not infer approval or seller consent, determine price or terms, promote policy, or bypass authority.

The execution request contains no price, terms, seller-message, seller-approval, or policy-promotion payload fields.
