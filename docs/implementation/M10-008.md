## Factory flow

The runner:

1. validates the community job manifest;
2. assembles exactly one governed profile of every required M10-006 profile type;
3. generates a fresh M10-003 onboarding bootstrap;
4. executes all eight M10-004 progressive stages;
5. captures deterministic stage receipts;
6. packages an immutable, non-published release candidate;
7. generates a release request containing candidate lineage and unresolved exceptions;
8. stops at the human release-authority gate.

## Authority boundary

The factory never:

- publishes a community;
- promotes a candidate;
- infers missing community or source assumptions;
- auto-approves a release request.

Every successful release request remains `BLOCKED_PENDING_HUMAN_APPROVAL` unless unresolved exceptions instead make it `BLOCKED_UNRESOLVED_EXCEPTIONS`.

## Retry / resume safety

A failed stage produces:

- no candidate package;
- no release request;
- the exact first failed/incomplete stage as the only valid resume point.

A retry cannot jump past that stage. Resume requests without prior stage state are rejected.

## Multi-community proof

Both accepted community configurations are represented through the same factory workflow:

- Rancho Vistoso, Arizona;
- Daybreak, Utah.

Their community/source assumptions remain in external manifests and governed profiles. Neither community is embedded as a reusable-core default.
