# M13-006A — Scenario Definition, Assumption Governance & Contract Freezing

Status: IMPLEMENTED — AWAITING ACCEPTANCE

## Purpose

Create immutable, versioned scenario-definition contracts that bind a subject to an exact certified baseline and a fully explicit typed assumption set while preserving a hard distinction between facts and assumptions.

M13-006A is governance only. It does not calculate scenario outcomes.

## Frozen boundary

A scenario contract records:

- scenario identity and version;
- community and subject identity;
- exact certified baseline snapshot id and SHA-256 fingerprint;
- source-linked facts;
- typed, source-attributed assumptions;
- lifecycle state (`DRAFT` or `READY`);
- supersession lineage;
- policy version; and
- deterministic contract fingerprint.

`READY` is immutable. Any later change requires a new scenario-contract version that references the superseded contract fingerprint.

## Hard prohibitions

M13-006A does not calculate scenarios, predict outcomes, recommend actions or prices, rank scenarios, select winners, compute hidden utility scores, make future-outcome claims, execute M12 actions, publish externally, silently default assumptions, use uncertified baselines, merge facts into assumptions, or mutate a READY contract.

## Acceptance boundary

M13-006A passes only if identical governed inputs produce identical hashes; ordering does not change semantic hashes; baseline certification and fingerprints are enforced; assumptions are typed and explicit; duplicate/colliding keys are rejected; READY contracts replay exactly and cannot be mutated; supersession creates a new version rather than altering history; and no decision/recommendation/execution fields exist in the contract model.

The next engineering boundary remains M13-006B only after real M13-006A acceptance evidence exists.
