# M8-029 — Freshness / Version UI

Status: IN_PROGRESS

## Purpose

Present governed temporal truth and version context without deriving recency from render time, inventing re-verification, or allowing historical/stale reports to appear current.

## Input contract

- Consumes only governed audience-safe freshness/version DTOs.
- Distinguishes report generation time from effective-as-of, verified-through, market-data-through, and builder-check dates.
- Consumes freshness states as governed inputs: CURRENT, AGING, STALE, HISTORICAL, UNKNOWN, NOT_APPLICABLE.
- Consumes explicit CURRENT/HISTORICAL report designation and a stable current-report path.
- May consume section-level governed freshness for property, market, evidence, and other approved sections.

## Behavior

- Public shows the minimal governed data dates plus current/historical status and stale warnings.
- Seller shows key data dates, report version, and section freshness while omitting report-generation time.
- Agent may show effective-as-of, generated date, report version, and full section freshness detail.
- Historical reports always display a historical banner and retain a stable current-report link.
- STALE state always displays an explicit stale warning.
- Generated/render time is never substituted for data freshness.
- No generic "updated" wording is produced.
- Unknown freshness is presented as unknown, not inferred current.
- A stale state never implies the underlying fact is false.
