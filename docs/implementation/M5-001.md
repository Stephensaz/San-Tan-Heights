# M5-001 — Release Persistence Completion

Status: ACCEPTED

## Scope
Established the durable persistence foundation for fleet releases without implementing later policy, membership-resolution, freezing, lifecycle, approval, rollout, rollback, or cancellation behavior.

## Added
- `operations.releases` governed by the existing `reference.release_state` registry.
- `operations.release_manifests` as the durable one-row-per-release home for future frozen membership/manifest evidence.
- `operations.release_items` for deterministic per-property / variant / optional-channel fleet targets and exact snapshot/report/render lineage.
- Reverse and lifecycle-supporting indexes without cascade deletion of historical release evidence.
- Python persistence models/repository with fail-closed enum/hash/ordinal validation and canonical JSON serialization.

## Contract boundary
Release Manager coordinates downstream services; this persistence layer does not directly perform generation, validation, publication, rollback, or recovery.

## Certification note
Live PostgreSQL execution remains required during production certification for FK, locking, grants, and transaction behavior.
