# M10-006 — Portability Remediation & Platform Hardening

Status: IN_PROGRESS

## Purpose

Take the explicit portability friction measured in M10-005 and harden the reusable platform so future community onboarding requires less manual remediation without hiding community-specific or source-specific behavior inside reusable core semantics.

## Frozen boundary

M10-006 owns remediation analysis, reusable/configurable abstraction improvements, adapter/configuration interfaces, validation hardening, regression expansion, and proof that accepted San Tan Heights and Rancho Vistoso pilot behavior remain stable after hardening.

M10-006 does not erase legitimate community differences, does not convert source-specific assumptions into silent core defaults, does not perform the third-community cold-start proof, does not publish a new community, and does not mutate accepted production baselines.

## Required implementation

- consume the exact M10-005 remediation ledger;
- determine which friction is legitimately reusable, configurable, community-specific, or source-specific;
- extract only genuinely reusable/configurable patterns;
- preserve source-specific interfaces where source behavior differs;
- preserve community-specific configuration where community semantics differ;
- add regression tests proving San Tan Heights behavior remains unchanged;
- replay the Rancho Vistoso pilot through the hardened platform;
- measure whether manual remediation is reduced without reducing governance;
- record all remaining irreducible portability friction explicitly.

## Acceptance boundary

M10-006 may be accepted only when every M10-005 remediation item has an explicit disposition, reusable hardening is covered by tests, no hidden community/source default is introduced, San Tan Heights regression remains clean, the Rancho Vistoso pilot replays successfully, remaining remediation is explicitly classified, and inherited certification gates pass.
