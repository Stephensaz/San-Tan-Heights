# M3-004 — Regeneration Queue Service

Status: ACCEPTED

Implemented idempotent regeneration queueing from governed dirty/rebuild triggers. Queueing resolves the current accepted snapshot, assigns registry-driven priority, calculates the deterministic job target key, reuses an existing active logical target, persists a QUEUED job, and emits REGENERATION_JOB_QUEUED in the caller transaction.

Live PostgreSQL execution of locking/lease behavior remains a production-certification environment gate.
