# M11-008 — Seller Intelligence Calibration & Version Promotion Framework

Status: ACCEPTED

## Purpose

Take M11-007 advisory calibration candidates and convert them into isolated candidate versions of Seller Intelligence rules that can be replayed, compared, approved, promoted, or rejected without mutating the currently accepted production baseline in place.

## Accepted calibration framework

M11-008 now:

- builds an immutable accepted Seller Intelligence rule baseline;
- creates isolated candidate rule versions bound to the exact parent version and parent fingerprint;
- accepts only governed M11-007 `REVIEW_CONDITION_CALIBRATION` candidates;
- rejects outcome-coverage-gap observations as direct rule changes;
- replays accepted baseline and candidate rules against identical historical fixtures;
- makes changed Day-7 / Day-10 / Day-14 review behavior explicit;
- records communication effects such as added or removed review guidance;
- blocks protected regression when an existing protected review trigger is removed;
- blocks any candidate that disables the governed Day-14 checkpoint;
- requires a separately created human approval bound to the exact candidate rule fingerprint;
- preserves rollback to the accepted baseline version and fingerprint;
- produces a package only with status `READY_FOR_M11_009_CERTIFICATION`.

## Baseline immutability

The accepted baseline is never edited in place.

A candidate receives:

- its own version ID;
- exact parent version ID;
- exact parent fingerprint;
- its own deterministic rule fingerprint.

Historical replay reads both versions without mutating either one.

## Regression boundary

Protected behavior fails closed.

A candidate cannot:

- remove a protected existing review trigger;
- disable the Day-14 always-review checkpoint;
- introduce unsupported rules;
- use non-boolean rule values;
- bypass exact parent lineage.

Regression remains visible in the replay comparison and blocks promotion-package generation even if a human approval record exists.

## Human promotion boundary

No candidate promotes automatically.

A promotion package exists only when:

- replay regression count is zero;
- an explicit human approval exists;
- approval status is `APPROVED`;
- the approval is bound to the exact candidate fingerprint.

The package is still not production promotion. It is only ready for M11-009 certification.

## Rollback boundary

Every promotion package retains:

- accepted baseline version ID;
- accepted baseline fingerprint;
- rollback version ID;
- rollback fingerprint;
- replay root fingerprint;
- approval ID.
