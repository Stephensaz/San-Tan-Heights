# M8-028 — What Changed UI

Status: IN_PROGRESS

## Purpose

Present deterministic, audience-safe semantic changes between two governed versions without deriving differences in the presentation layer, inventing causation, or implying that a knowledge update proves a physical property change.

## Input contract

- Consumes only certified change DTOs backed by one upstream semantic-diff hash.
- Requires the same property identity and the same governed audience across the full change set.
- Binds displayed changes to previous/current semantic fingerprints.
- Uses the current audience policy to authorize both current content and any historical value shown.

## Behavior

- Supports governed change types for added/retired findings, value/state/confidence/freshness changes, evidence/limitation changes, corrections, resolved conflicts, diagram/media changes, and market-context changes.
- Suppresses WORDING_ONLY and NO_SEMANTIC_CHANGE presentation noise.
- Seller/Public omit DETAIL-only changes; Agent may retain certified DETAIL context.
- Groups visible changes deterministically as Newly Verified, Updated, Corrected, Evidence Updated, and Market Context Updated.
- Corrections remain explicitly grouped as Corrected and cannot be disguised as a routine refresh.
- Unauthorized historical values are withheld under the current audience policy rather than leaked from prior versions.
- A first report or an empty meaningful change set omits the What Changed panel.
- Knowledge changes remain marked as knowledge changes; the UI does not assert physical change, causation, or re-verification.
- Raw report diffs, private QA/model history, and cross-audience history are not accepted.
